# Repository cleanup review

Reviewed September 20, 2026. Scope: the readiness implementation from `c84b741` through `0c0cb6c`, followed by the cleanup branch. Seven reviewers covered reuse, code quality, efficiency, breaking changes, test coverage, model context and change size. Duplicate reports are combined below; every reported issue is retained.

## Findings and disposition

1. **P1, fixed: lost asynchronous benchmark errors.** [benchmark.py](../unrender/serving/benchmark.py), line 225. Completed tasks previously removed themselves before their exceptions were observed. Nested task groups now stop admission on failure and prevent a partial success summary. Deep JSON nesting is rejected as invalid input by [validate.py](../unrender/schema/validate.py), line 43. Reported by quality and efficiency reviewers.
2. **P1, fixed: GPU monitoring failed open.** [benchmark.py](../unrender/serving/benchmark.py), line 39. Launch, timeout, malformed and nonfinite telemetry now stop the benchmark. A successful initial sample is required before dispatch; timed-out children are killed and reaped. Reported as P1 by quality and P2 by efficiency; the higher severity is retained.
3. **P2, fixed: per-response full-ledger export distorted timings.** [benchmark.py](../unrender/serving/benchmark.py), line 277. Durable outcome commits remain per attempt; portable snapshots are exported before dispatch and during cleanup, removing quadratic snapshot work from response handling. Reported by efficiency.
4. **P2, fixed: stale diagnostic prediction readers.** [failures.py](../unrender/eval/failures.py), line 23, and [ensemble.py](../unrender/eval/ensemble.py), line 90, now use the authoritative ledger loader. The historical [scoreboard.py](../analysis/scoreboard.py), line 52, explicitly rejects live ledgers so its input hash still identifies the snapshot it scores. Reported by reuse.
5. **P2, fixed: gallery scores bypassed the primary metric.** [failures.py](../unrender/eval/failures.py), line 31. Gallery ranking now calls `score_prediction`; repaired JSON and stale cached predictions cannot receive primary accuracy credit. Reported by reuse.
6. **P1, fixed: normal retention broke training resume.** [checkpoints.py](../unrender/train/checkpoints.py), line 201. Each retained checkpoint's own bytes are verified; only the selected resume state's best-model dependency must still exist. Obsolete best references in older retained saves no longer prevent valid resume. Missing selected-best weights and incomplete newer saves still fail. Reported by breaking-change review.
7. **P2, fixed: historical evaluation paths silently failed.** [io_utils.py](../unrender/io_utils.py), line 19, rejects historical repository-relative image paths with an explicit explanation. [modal_train.py](../modal_train.py), line 947, requires current dataset names before standalone cloud dispatch. Frozen files remain unchanged; old scores are reproduced offline. Reported by breaking-change review.
8. **P2, fixed: chained evaluation validation happened after paid training.** [modal_train.py](../modal_train.py), line 443. `--eval-after` now validates current dataset names and nonnegative limits before local preflight/spawn and before worker training. The follow-up review found this remaining call site while checking finding 7.
9. **P2, fixed: SDK minimum versions did not support the calls in use.** [pyproject.toml](../pyproject.toml), line 42, now requires OpenAI 3.16.2+ and google-genai 2.24.0+ within their major versions. Both exact floors were installed in an isolated environment and their request/retry interfaces checked without inference. Reported by breaking-change review.
10. **P2, fixed: Gemini's cloud image lacked evaluation imports.** [modal_train.py](../modal_train.py), line 153. Its image now includes NumPy and Matplotlib, required by the provenance reader, and pins the verified Gemini SDK. Reported by breaking-change review. The image declaration is corrected; no new cloud deployment was performed in this cleanup.
11. **P1, fixed: reference serving could truncate image tokens.** [transformers_server.py](../unrender/serving/transformers_server.py), line 138, explicitly disables tokenizer truncation. An HTTP-level regression verifies that 2,500 prompt tokens survive the reference path. Reported by context review.
12. **P3, fixed: training comments repeated audit history.** [sft_lora.py](../unrender/train/sft_lora.py), line 221. Comments now explain deterministic validation and within-objective selection; historical rationale remains in the archive. Reported by quality.
13. **P2, addressed through review stages: the earlier readiness diff was too large.** [REVIEW_READINESS_PLAN.md](REVIEW_READINESS_PLAN.md), line 7. The reviewed historical range contains 25,409 changed text lines across 236 files, including 14,491 code/test/configuration/analysis lines. This is a retrospective review-organization finding; merged history was preserved. Reported by change-size review.

The test reviewer investigated old queued-job reservation rejection and withdrew it as a defect: [API.md](API.md), line 203, explicitly requires rejection before dispatch rather than silently increasing reserved capacity. Existing tests cover no dispatch and exactly one refund. The context reviewer found Codex-specific transcript/Rust rules inapplicable to this one-shot Python extraction system. Hash helpers with different byte and mutation contracts were kept separate.

## Review stages

The cleanup uses separate commits for mechanical moves, documentation edits, benchmark fixes, checkpoint recovery and evaluation integration. Each complex code-fix commit is below 500 changed lines. The documentation commit includes preserved copies of long historical records; review its new entry points separately from the archive copies.

For a deeper retrospective review of the earlier implementation, start with the independent 135-line worker/concurrency/config/test slice. Then review parser → evaluation identity/metrics/comparison → attempt ledger/collector/cloud persistence → product versioning/receipts → synthetic provenance/review gates → training contracts/integration → serving. Checkpoint sealing plus its tests is a 446-line independent stage; weighted loss is 190 lines, collator 174 and recipe identity 198. Keep generated locks and evidence beside their relevant code, without treating them as logic changes.
